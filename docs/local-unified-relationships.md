# 统一关系与主动互动回应度

Mai_life 的本地集成通过 `Alcpare.identity.get_relationship` 获取身份与好感。
人工名单管理主人权限；印象卡片管理总好感、信任、熟悉等维度及朋友/群友的动态切换。
好感采用印象卡片原始参考刻度（默认 0～10，实际数值可以越界），不转换或复制成另一套温度。

| 项目 | Mai_life 原内部机制 | 当前统一机制 |
| --- | --- | --- |
| 评分来源 | 每天按聊天次数、回应主动消息加温，长期无消息降温 | 原印象卡片评分；回应情况作为小权重长期信号 |
| 分值 | 0～100，朋友封顶80 | 原始好感与多维分值，允许越界 |
| 关系 | 陌生、认识、熟悉、亲近、知己 | 既有人工身份及群友/朋友动态关系 |
| 主人权限 | Mai_life 私聊档案里的 role | 身份插件的手动主人名单；高分不会授予主人权限 |
| 更新 | Mai_life 每日单独结算 | 原有评分工具及一个按天幂等的回应观察接口 |

## 配置与接口

- Mai_life：`context.relationship_provider="existing_identity"`、
  `context.outreach_feedback_enabled=true`。内部 `relationship_enabled=false` 保持关闭。
- 印象卡片：`outreach.enabled=true`。其余细节在同一配置节调整。
- `com.0-hz.impression-card.get_relationship` 的原动态关系字段保持兼容，
  新增 `affinity` 原始总分/各维度/参考刻度，以及 `outreach` 累计影响。
  主人虽被保护不参与自动身份升降，其真实好感仍可读取。
- `Alcpare.identity.get_relationship` 返回已核实身份来源、角色及好感，
  不依赖内存里是否还有最近一条用户消息。
- `com.0-hz.impression-card.apply_outreach_feedback` 只接收观察日和结果，
  不接收聊天正文。按平台、用户、日期去重，分数与审计记录在同一事务写入。
- Mai_life 的公开关系接口、管理指令、WebUI、主动评分、群转私排序、
  私人日记/书柜权限都使用统一查询结果。接口异常明确显示未知，不读取旧温度代替。

## 回应观察规则

只从启用后的新记录开始统计，不追溯处罚旧消息。
实际发送成功且处于清醒、可打扰状态的主动私聊才建立观察日；
发送失败、Planner 决定沉默和睡眠期间的消息不计入。
一天无论发多少条，只形成一项观察；自当天最后一条有效主动消息起等待48小时。
期间任何真实私聊互动均算回应，不要求引用或逐条作答。
已知临时忙碌、关闭主动私聊、额度调零或设置免打扰时，尚未结束的观察排除。

默认连续前2个无回应的有效观察日不扣分，第3个开始每个观察日总好感 -0.02；
有回应时 +0.01。已存在疏远影响时，每个恢复互动观察日先恢复0.04，逐渐回到原水平。
后来主动回来聊天也提供恢复信号，无需等机器人再开场。
该机制的累计总好感影响限制为 -0.6～+0.3；只同步影响回应度，信任和熟悉不受它直接加减。
原有模型评分仍判断其他真实互动内容，提示词与写入逻辑阻止重复修改回应度。

停用某人的主动私聊与免打扰规则继续有效。主人权限、私人内容访问和用户额度不由回应度变化决定。
不向用户播报扣分，不用关系变化催促回复。
