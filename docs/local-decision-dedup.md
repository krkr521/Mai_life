# Decision 语义去重

启用 `schedule.semantic_dedup_enabled=true`，默认回看3天，
天数由 `schedule.semantic_history_days` 调整。

审核固定使用宿主的 `decision` 任务，跟随其现有模型配置；
不受 Mai_life 后台生成的 `models.model_override` 覆盖，不更改主程序其他模型路由。
生成仍使用原有日程/场景模型，Decision只判断是否过于相近并给出修改理由。

## 审核位置

1. 日程生成：与近期日程和场景做语义对照。开启时替代“半数节点整句相同”的近期重复规则；
   不因只换天气、措辞、时间顺序就认为是新事件。
2. 场景细化：对照前几天及今天已经结束的场景，避免日程标题不同、具体趣事又相同。
3. 主动消息正文：在平台发送前审核实际回复草稿，对照同一个用户已经收到的主动消息。
   采用宿主回复器的重生成流程，把审核理由带入下一轮，不只审核候选话题标题。
   用户主动发起的正常回复、群聊回复、其他插件的任务不进入这项主动去重。

睡眠、用餐、例行工作可以重复，固定兴趣不属于禁止话题。
有不同经历或明确新进展的同一创作线可以继续；
真实用户在此前分享后要求继续聊同一主题的消息也会提供给Decision作为参考。
旧书柜标题保留类型，小说、日记等不能被误当成同名歌曲或真实活动继承。

## 历史与失败处理

- 发送前的候选、模型生成但没发出的草稿、失败发送不进入已发送历史。
- 只有平台确认发送成功、且归属于持久化主动事件的文字才记入；
  分段发送按事件合并，重复回调保持幂等，历史按用户隔离。
- 部署时可以利用主消息库中已有的 `mai_life_active_task_id` 标签回填近期真实记录，
  不依靠消息内容猜测来源，也不改变过去的主动额度或回应度。
- 日程/场景最多尝试3次；每次语义拒绝会带理由重新生成。
  审核服务不可用或多次不合格时显式报错，保留已有日程，不写入未经审核的模板。
- 主动正文采用宿主的有限重试；耗尽尝试或审核不可用时取消本次发送，不扣实际发送额度。
- 既有已保存日程不会因热加载被无条件覆盖，之后的生成/细化和主动正文使用新审核。
  每日配置的日程重生成流程也使用Decision审核。

管理员只读测试接口 `webui_semantic_probe` 绑定在 overview 的 `semantic_probe` 查询，
只返回判断与理由，不生成日程、不发送消息。用量记录类型为 `semantic_*`，任务名应为 `decision`。
