# 主动开场的历史消息引用

Mai_life重载会清空当前入站消息的内存状态。宿主仍会恢复真实私聊历史，主动任务也仍会进入Planner。
如果插件把空的内存编号解释成“本轮没有可引用消息”，Planner会因此等待，无法调用要求msg_id的原生reply工具。

现在仅为Mai_life主动任务恢复路由引用：

1. 从绑定用户的持久化互动记录读取最近已记录的真实消息编号。
2. 要求该编号仍出现在当前Planner的原始消息末尾标记中，内部主动任务编号不能代替。
3. 通过现有message.get_by_id能力核验原始编号、发送者、私聊会话及非通知属性。
4. 在当前主动任务指引中提供已核验编号，明确它仅用于定位会话，不能把历史内容当新来信重答。

不把恢复结果写回入站身份状态，不恢复临时勿扰工具令牌；清理上下文后已不可见的旧引用不重新引入。
主动开场不在QQ里引用这条旧消息。普通被动回复、其他插件任务和既有权限边界保持原有流程。
额度、睡眠和个人勿扰仍按发送前检查执行；没有合适内容时Planner仍可沉默。

诊断中的planner_no_reply计数表示候选过期前没有成功发送，包含沉默、超时和调用失败，不能仅凭计数推断模型主观决定。
